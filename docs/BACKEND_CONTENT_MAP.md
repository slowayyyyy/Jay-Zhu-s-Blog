# 后台与前台内容对照

更新：2026-09-04。后台地址：`/admin/`。

## 保存后怎样生效

后台“保存/发布”将内容提交到 GitHub main；Cloudflare Pages 构建成功后，新页面才生效。保持打开的旧页面不会自动换成新构建，请刷新。不要通过清理音乐来刷新文案。若部署失败，旧站仍保留，先检查构建日志。

## 常用位置

下表中的“站点设置”指后台左侧“苍蓝回廊设置”。

### 首页文字与图片同步（2026-09-04）

首页按“逐字出现 → 完整停留 2 秒 → 逐字退场 → 下一张图与下一句首字同时开始”的节奏播放。长句自然需要更长时间，无须在后台计算秒数。中文、日文、英文与组合 emoji 都按完整字符处理。

仍在原来的位置管理短句池、桌面图片和手机图片，各自顺序循环，数量不必相等。只有一句时重复该句配合换图；只有一张图时保持图片、继续轮播短句。短句池清空后使用备用介绍。

下一张图提前加载；网速慢时两者一起等待，加载失败/超时保留旧图并继续文字，后续跳过失败图片，避免黑屏或卡死。切到其他标签页、滚出首屏或播放背景视频时暂停相应循环，返回后继续，不补播积攒的动画。

键盘左右键或在图片上横向滑动可同时切换文图；空格暂停/恢复（输入框和按钮等交互控件不会被拦截）。关闭壁纸轮播或选定固定壁纸时尊重访客选择，不强制换图。系统启用“减少动态效果”时显示完整静态文字并停止自动轮播。

隐藏首页文字或访问其他页面时，图片使用原有独立轮播间隔。本次没有恢复开场动画，也不改变音乐播放。

## 音乐管理与随机播放

- 新增：在“音乐歌单”添加一条，填写歌名/歌手，上传音乐，选择封面和歌词，再保存。R2 上传完成不代表页面已发布。
- 修改：展开对应歌曲，替换该条的音乐、封面、歌词或翻译；这些字段按条目配对，不按文件名猜测。
- 移出：删除整个歌单条目再保存；“清空音乐文件”只清空地址，该条不进入前台播放队列，其余字段保留。
- 云端音乐原文件不会因清空、替换、移出或修改签名而自动删除。永久清理由站长核实引用并另行明确授权；后台没有自动删除入口。
- 歌词支持直接粘贴 LRC、站内路径或 HTTPS URL；现有 KRC 已转换成 karaoke-v1 JSON，可逐字变色。原始 KRC 不能直接作为网页歌词地址。
- 每条中文翻译按解析后的歌词行顺序配对；不计 LRC 元信息。更换歌词版本后要同步调整翻译。访客可以开关翻译。
- 随机模式每轮使用 Fisher–Yates 打乱歌单，逐首取出；这一轮九首听过后再重新打乱，轮次交界避免紧接着重复同一首。
- “上一首”沿本次页面会话真实播放历史返回；返回后“下一首”先沿历史前进。手动选择未播歌曲会从剩余队列移除，避免自动抽中两遍；手动重选已播歌曲属于访客主动重复。
- 切换到随机模式从当前歌曲建立新一轮；普通页内跳转共享播放器，完整刷新会重建队列。只有一首歌时自然循环，两首时必然交替。

## 保留但停用的字段

旧 `opening`、`hero.note/primaryCta/secondaryCta`、`home` 的旧分支入口文案仍在 JSON、恢复标签与离线备份中。当前版不渲染这些旧组件，因此后台隐藏其控件，避免“能改却无效”；没有删除用户数据，也没有恢复开场动画。

“视觉素材索引”只是素材路径与用途的登记表。改其中的用途或图片不会自动替换已引用它的页面；在对应壁纸、乐境、头像、歌单或相册字段选择该素材才生效。索引变更也不会删除文件。

## 管理范围边界

后台管理大部分个人内容，不是完整运维控制台。页面结构、菜单层级、字体、主题布局、服务开关、评论服务接入等仍由代码配置；友链补充模板是高级 MDX 编辑。Bilibili 收藏与 Umami 报表在各自平台管理。服务器状态读取真实状态，不应手工填写 CPU 百分比。

OAuth、R2、Cloudflare 和 AI 接口密钥只放平台 Secret/环境变量，不能写进这里的公开 JSON。文章摘要目前是作者维护的文字，不会自动调用 GPT。
